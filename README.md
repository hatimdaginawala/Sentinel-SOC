##  Overview

SentinelSOC is an enterprise-grade Security Operations Center (SOC) and Security Information & Event Management (SIEM) platform designed to centralize, monitor, analyze, correlate, and respond to security events generated by various network devices, operating systems, servers, applications, and security appliances.

The platform simulates a real-world Security Operations Center used by enterprise organizations, providing security analysts with a centralized dashboard for monitoring threats, managing incidents, tracking assets, generating reports, and analyzing organizational security posture.

### Key Capabilities

- **Centralized Log Collection** - Ingest logs from multiple sources
- **Event Normalization** - Standardize different log formats
- **Real-time Threat Detection** - Detect suspicious activities using rules
- **Alert Management** - Generate and manage security alerts
- **Incident Response** - Track and manage security incidents
- **Asset Management** - Inventory and track security assets
- **Threat Intelligence** - Manage Indicators of Compromise (IoCs)
- **Risk Scoring** - Calculate organizational risk scores
- **Reporting** - Generate executive and operational reports
- **Audit Logging** - Complete audit trail of all activities

##  Architecture

### Layered Architecture

```
┌─────────────────────────────────────────────┐
│                  Frontend                    │
│         (HTML/CSS/JavaScript)              │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│                 REST API                    │
│            (Express.js Routes)              │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│               Controllers                   │
│          (Request/Response)                │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│                Services                     │
│             (Business Logic)                │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│                 Models                      │
│           (Mongoose Schemas)                │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│                MongoDB                      │
│             (Database)                      │
└─────────────────────────────────────────────┘
```

### Principle Layers

Each layer has a single responsibility:

- **Routes** - Define API endpoints and validation
- **Controllers** - Handle request/response, coordinate services
- **Services** - Implement business logic
- **Models** - Define data schemas and database operations
- **Middleware** - Authentication, validation, logging, error handling

##  Installation

### Prerequisites

- Node.js 18.x or higher
- MongoDB 6.x or higher
- npm or yarn

### Step 1: Clone the Repository

```bash
git clone https://github.com/your-username/sentinel-soc.git
cd sentinel-soc
```

### Step 2: Install Backend Dependencies

```bash
cd backend
npm install
```

### Step 3: Install Simulator Dependencies

```bash
cd simulators
npm install
```

### Step 4: Configure Environment Variables

Create a `.env` file in the `backend` directory:

```env
# Server Configuration
PORT=3000
NODE_ENV=development

# Database Configuration
MONGODB_URI=mongodb://127.0.0.1:27017/sentinel_soc

# JWT Configuration
JWT_SECRET=your-super-secret-jwt-key-change-this-in-production
JWT_EXPIRY=7d
JWT_REFRESH_SECRET=your-refresh-secret-key-change-this-in-production
JWT_REFRESH_EXPIRY=30d

# Security Configuration
BCRYPT_ROUNDS=12
CORS_ORIGIN=http://localhost:3000
RATE_LIMIT_WINDOW=15
RATE_LIMIT_MAX=100

# API Configuration
API_PREFIX=/api/v1
```

### Step 5: Seed the Database

```bash
cd backend
node src/seed.js
```

This will create:
- 3 Organizations (Acme Corporation, Global Finance Inc, Healthcare Systems)
- 7 Users with different roles
- 10+ Assets
- 9 Log Sources with authentication tokens

### Step 6: Start the Server

```bash
# Development mode with auto-reload
npm run dev

# Production mode
npm start
```

### Step 7: Start Log Simulators

```bash
cd simulators

# Run all simulators
npm run all

# Or run individually
npm run windows
npm run linux
npm run apache
npm run nginx
npm run suricata
npm run snort
npm run firewall
```

##  Authentication & Authorization

### Authentication Flow

1. User submits credentials to `/api/v1/auth/login`
2. Server validates credentials and returns JWT access token
3. Client includes token in `Authorization: Bearer <token>` header
4. Server validates token on protected routes
5. Token expires and can be refreshed using refresh token

### Roles & Permissions

| Role | Permissions |
|------|-------------|
| **Super Admin** | Full system access |
| **Security Admin** | Manage assets, rules, notifications |
| **SOC Analyst** | Monitor logs, alerts, investigate incidents |
| **Incident Responder** | Handle and resolve incidents |
| **Auditor** | Read-only access for compliance |

### RBAC Implementation

- Every API endpoint validates permissions
- Middleware `authorize(permission)` checks user permissions
- Super admin bypasses all permission checks

##  Security Features

### Implemented Security Controls

- **JWT Authentication** - Stateless authentication with refresh tokens
- **Password Hashing** - bcrypt with salt rounds
- **Rate Limiting** - Prevent brute force attacks
- **Helmet.js** - Security HTTP headers
- **CORS** - Controlled cross-origin requests
- **Input Validation** - Express-validator for all inputs
- **Data Sanitization** - Prevent injection attacks
- **Environment Variables** - No hardcoded secrets
- **Audit Logging** - Complete audit trail
- **RBAC** - Granular access control

### Security Best Practices

- Passwords never stored in plain text
- Sensitive data not exposed in API responses
- HTTPS ready for production
- MongoDB injection prevention
- XSS prevention through sanitization

### Production Considerations

1. **Set strong JWT secrets** in .env
2. **Enable HTTPS** with Let's Encrypt
3. **Use MongoDB Atlas** or self-hosted with replication
4. **Configure firewall** and restrict ports
5. **Set up monitoring** and alerting
6. **Regular backups** of MongoDB
7. **Use PM2** or similar for process management

  -H "Content-Type: application/json" \
